# gyro_z 语义统一设计

## 背景

当前项目中，`gyro_z` 在 `imu.c` 内已经按实车标定系数 `0.082f` 进行缩放。该缩放的设计目标不是保留标准物理角速度单位，而是让小车原地旋转一圈后，累计结果接近 `360`，直接服务于当前控制链。

但仓库内仍有若干注释和调试代码把 `gyro_z` 当作标准角速度使用，导致同一变量在不同文件中的语义不一致。

## 目标

- 保留 `imu.c` 中现有 `gyro_z` 赋值公式不变
- 全项目统一把 `gyro_z` 视为“标定后的控制反馈量”
- 清理旧的重复缩放逻辑
- 不新增新的原始陀螺仪变量
- 不调整当前控制器参数和实车调试结果

## 方案

采用最小改动方案：

1. 保留 `gyro_z` 名称和现有计算公式
2. 修改 `imu.h`、`a_run.c`、`pid.c` 等处注释，去掉“度/s”“标准角速度”等误导表达
3. 清理 `test.c` 和 `debug_view.c` 中对 `gyro_z` 的再次 `0.082f` 缩放
4. 保留调试显示中的 `gyro_z` 输出，但解释为控制反馈量

## 非目标

- 不引入 `gyro_z_raw`
- 不重构 Pure Pursuit 或姿态解算
- 不调整 PID 参数
- 不改动 `Gyr_filt.Z` 的物理量语义

## 风险控制

- 只改注释和重复缩放点，不改核心控制公式
- 用独立检查脚本验证：
  - `imu.h` 不再把 `gyro_z` 标成 `deg/s`
  - `test.c` 不再重复乘 `0.082f`
  - `debug_view.c` 不再重复乘 `0.082f`
  - `imu.c` 保留现有标定公式
