# 圆环圆筒识别仲裁计划

## 1. 背景与目标

当前圆环入口主要依赖四路电感特征判断。圆筒过程中，尤其是圆筒过顶后从 `vzc` 负值回到接近平地时，电感形态可能短暂接近圆环入口特征，导致圆环状态机误触发。

目标是在圆环识别前增加一层“赛道元素仲裁”，让代码先判断当前是否轮到圆环识别，再决定是否允许圆环入口触发。

初版重点解决当前赛道模式：

```text
左圆环 -> 圆筒 -> 左圆环 -> 圆筒 -> ...
```

第二次圆筒完成后继续重复，不自动完赛。

## 2. 当前需求整理

1. 圆环和圆筒的先后关系由发车前人工确认。
2. 当前主要模式是一圈包含 `左圆环 -> 圆筒`，并循环重复。
3. 后续赛道可能出现一个左圆环、一个右圆环，也可能一圈只有一个圆环加圆筒。
4. 当前没有可靠的起点/终点检测。
5. 圆筒完成后可以重新打开圆环识别，不在第二次圆筒后自动关闭。
6. 圆筒完成条件已按 `vzc` 过顶、回平、稳定延迟三段式敲定。

## 3. 推荐总体方案

新增一个轻量的赛道元素仲裁状态机，建议命名为 `TrackElementGate`。

第一版直接放在：

```text
project/user/a_run_mode.c
project/user/a_run_mode.h
```

原因是圆环状态机、启动状态机和赛道阶段逻辑已经集中在 `a_run_mode` 模块，初版放在这里接口最少。后续如果元素仲裁变复杂，再考虑拆分独立模块。

它只负责管理当前期望元素，不直接控制电机：

```text
ELEMENT_NONE
ELEMENT_LEFT_RING
ELEMENT_RIGHT_RING
ELEMENT_CYLINDER
```

初版实际启用：

```text
ELEMENT_LEFT_RING
ELEMENT_CYLINDER
```

运行流程：

```text
发车后：
    当前期望左圆环，允许左圆环入口识别

左圆环完整出环后：
    关闭圆环入口识别
    当前期望圆筒

圆筒完成后：
    当前期望左圆环
    重新允许左圆环入口识别

如此循环
```

这样在期望圆筒阶段，即使圆筒电感特征短暂像圆环，也不会进入圆环状态机。

## 4. 圆环侧改动

当前圆环状态机入口在：

```text
project/user/a_run_mode.c
circle_check_l()
```

建议为圆环入口识别增加上层允许条件：

```text
allow_left_ring_entry
```

接口从：

```c
void circle_check_l(void);
```

调整为：

```c
void circle_check_l(uint8 allow_entry);
```

规则：

```text
current_state == no_ring:
    只有 allow_left_ring_entry == 1，才允许检测左环入口特征

current_state != no_ring:
    不因 allow_left_ring_entry 变 0 而中断
    已进入圆环后必须继续跑完整个圆环流程
```

这样可以避免已经入环后被上层仲裁状态打断。

同时建议把当前“一次命中就确认圆环”的入口逻辑改成连续确认：

```text
圆环入口特征连续 3 次命中
并且当前期望元素是左圆环
才进入圆环状态机
```

已敲定：

```text
入口连续确认次数：3 次，约 30ms
```

已确认保留 `circle_check_l()` 内当前的 `stop = 1` 行为，第一版不改变圆环触发时的现场调试/停车标志语义。

圆环完成事件为 `a_run_mode.c` 内部一次性事件，不对外暴露接口。

## 5. 圆筒侧改动

当前已有圆筒过顶思路在：

```text
project/user/FUYA.c
fuya_update_cylinder_peak_10ms()
```

该函数当前已经包含圆筒过顶检测，并在过顶时临时覆盖 `app.angle.A_1 / B_1 / C_l`。后续不建议再让 `FUYA.c` 维护圆筒完成状态机；圆筒完成状态机统一放到 `a_run_mode.c/.h`，和 `TrackElementGate`、圆环状态机放在同一处。

建议将 `fuya_update_cylinder_peak_10ms()` 的职责拆分：

```text
1. a_run_mode.c 负责圆筒过顶、回平、稳定延迟和完成事件
2. FUYA.c 只负责进入/退出圆筒过顶 angle 参数模式
```

圆筒状态机放在：

```text
project/user/a_run_mode.c
project/user/a_run_mode.h
```

状态机建议为：

```text
CYL_WAIT_TOP
CYL_WAIT_GROUND
CYL_STABLE_DELAY
```

`FUYA.c/.h` 只开放底层参数切换接口：

```text
project/user/FUYA.c
project/user/FUYA.h
```

建议接口：

```c
void fuya_apply_cylinder_peak_angle(void);
void fuya_restore_cylinder_peak_angle(void);
```

语义：

```text
fuya_apply_cylinder_peak_angle():
    备份 app.angle.A_1 / B_1 / C_l
    切换到圆筒过顶专用 angle 参数

fuya_restore_cylinder_peak_angle():
    恢复圆筒过顶前的 angle 参数
```

判断逻辑初稿：

```text
CYL_WAIT_TOP:
    vzc <= -0.85 连续 2 次
    确认已经经过圆筒最高点

CYL_WAIT_GROUND:
    已经过顶后，等待 vzc >= 0.98 连续 3 次
    确认车身回到接近平地

CYL_STABLE_DELAY:
    再等待 100ms
    防止刚下圆筒时姿态和电感还没有稳定

稳定延迟结束：
    恢复 angle 参数，返回一次圆筒完成事件，然后圆筒状态回到 CYL_IDLE
```

关键要求：

```text
必须先经历 CYL_WAIT_TOP，再允许判断回平。
否则发车时 vzc 本来接近 1，会被误判为圆筒完成。
```

如果进入圆筒阶段后长时间没有检测到顶部，第一版不自动跳过圆筒，也不自动重新开放圆环识别。这样宁可让状态停在 `CYL_WAIT_TOP` 并通过菜单暴露问题，也不要在未确认圆筒完成时放行圆环，避免误触发回到原问题。

## 6. 调度位置

建议继续放在 10ms 状态环中，不放入 5ms 高频控制环。

相关位置：

```text
project/user/a_run.c
run_time_2()
```

初步调度顺序：

```text
1. scan_track_max_value()
2. a_run_mode_update_start_state()
3. 同步 flat_statr = a_run_mode_get_start_state()
4. a_run_mode_update_track_element_gate()
5. gyro_integrals()
6. lost_lines()
7. dianya_jiance()
8. 负压相关更新
9. soft_timer_update_10ms()
```

注意：

```text
gyro_integrals() 依赖 ring_data.distance 和 ring_data.gyro_flat。
它应保持在圆环状态机更新之后调用。
```

`a_run_mode_update_track_element_gate()` 内部根据当前期望元素决定：

```text
当前期望左圆环：
    调用 circle_check_l(1)
    消费内部圆环完成事件

当前期望圆筒：
    调用 circle_check_l(0)，禁止新的圆环入口识别
    推进 a_run_mode.c 内部圆筒状态机
```

停车或非运行态时：

```text
TrackElementGate 重置回序列起点，即期望左圆环。
圆环状态机复位。
圆筒状态机复位，并恢复 angle 参数。
```

## 7. 配置方式

初版不做复杂的可编辑元素数组，但菜单预留模式切换项：

配置字段加到：

```text
project/service/eeprom.h
AppStartConfig
```

字段：

```c
int16 track_mode;
```

默认值：

```text
track_mode = 0
```

```text
模式 0：左圆环 -> 圆筒，循环
```

代码结构预留：

```text
模式 1：右圆环 -> 圆筒，循环
模式 2：左圆环 -> 右圆环 -> 圆筒，循环
模式 3：右圆环 -> 左圆环 -> 圆筒，循环
```

右环本轮只预留枚举和模式，不实现完整右环识别，避免一次改动过大。

菜单 `trk_mode` 需要支持预留模式切换，即使第一版只有模式 0 有完整行为。选择未实现的右环相关模式时，统一回退到模式 0，避免现场误选后进入不可控的空识别状态。

调试读取接口放在：

```text
project/user/a_run_mode.h
```

建议接口：

```c
int8 a_run_mode_get_expected_element(void);
int8 a_run_mode_get_cylinder_state(void);
```

## 7.1 圆环完成事件通知

圆环完成事件由 `circle_check_l()` 在出环确认成功、即将从 `out_ring` 回到 `no_ring` 时上报。该事件只在 `a_run_mode.c` 内部由 `TrackElementGate` 消费，不对外暴露接口。

事件触发点：

```text
out_ring 阶段中，满足电感重新平衡并确认 500ms 后：
    1. 清理 ring_data
    2. current_state 回到 no_ring
    3. 置位 ring_finish_event
```

`TrackElementGate` 在 10ms 状态环中消费该事件：

```text
当前期望元素是左圆环
并且 ring_finish_event == 1:
    切换到期望圆筒
```

事件必须是一次性事件，避免同一次出环完成被连续多个 10ms 周期重复消费。


## 9. 最小落地范围

第一版建议只做：

```text

5. 圆筒完成使用 vzc 过顶、回平、稳定延迟
```

第一版暂不做：

```text

```

## 10. 已敲定结论

当前计划细节已全部敲定，可进入实现计划拆分。

```text
圆筒状态机放在 a_run_mode.c/.h。
FUYA.c/.h 只提供圆筒过顶 angle 参数应用/恢复接口。
track_mode 加入 AppStartConfig，默认 0。
未实现的右环相关模式统一回退模式 0。
圆环完成通过 a_run_mode.c 内部一次性事件通知。
停车或非运行态时重置回期望左圆环。
```

## 11. 当前推荐初始参数

当前已敲定参数：

```text
圆筒顶部阈值：vzc <= -0.85
圆筒顶部确认：2 次，约 20ms
圆筒回平阈值：vzc >= 0.98
圆筒回平确认：3 次，约 30ms
圆筒稳定延迟：100ms
圆环入口确认：3 次
```

现场调试方向：

```text
圆筒结束后仍误开圆环：
    增大稳定延迟到 300ms~500ms
    或提高圆环入口确认次数

圆环重新开放太晚：
    降低稳定延迟到 100ms
    或降低回平确认次数
```
