# 电感排布与弯道控制分析

## 文档目的

本文用于统一当前四电感排布、`Err` 公式的物理含义，以及它与参考文章“差比和差”思路的区别，便于后续继续讨论：

- 高速循迹
- 急弯提前量
- 圆桶内壁等持续大曲率场景
- 单轮空转与打滑检测

本文默认以下映射已经确认：

- `ad1 = L`：左外侧横电感
- `ad2 = LM`：左内侧纵电感
- `ad3 = RM`：右内侧纵电感
- `ad4 = R`：右外侧横电感

## 当前电感排布的几何意义

当前车体两侧各布置一横一纵两个电感：

- 左侧为“左外侧横电感 + 左内侧纵电感”
- 右侧为“右外侧横电感 + 右内侧纵电感”
- 两个横电感位于车体最外侧
- 两个纵电感位于中间偏内侧

这意味着四个电感在控制中的角色并不等价：

- `L - R` 主要反映横向位置偏差
- `LM - RM` 主要反映弯道趋势或航向趋势
- `L + R` 主要提供横向总场强参考

因此，这套排布不是简单的“四路并列采样”，而是天然带有“位置量 + 趋势量”的分工。

## 当前代码中的误差公式

在 `project/user/ADC.c` 中，当前 `Err` 可抽象写成：

```text
x = L - R
y = LM - RM
S = L + R

e_abs = (A * x + B * y) / (A * S + C * |y|)
```

其中：

- `x` 是横向不平衡量
- `y` 是纵向趋势量
- `S` 是横向总信号
- `A / B / C` 分别对应 `A_1 / B_1 / C_l`

从控制意义上看：

- 分子中的 `A*x` 决定基础回中能力
- 分子中的 `B*y` 给控制器提供弯道提前量
- 分母中的 `C*|y|` 在弯道增大时抬高分母，相当于做统一的增益收缩

因此，当前算法更准确地说，是“带弯道增益调度的差比和”。

## 与参考文章“差比和差”的区别

参考文章的核心思路更接近：

```text
e_signed = (A * x + B * y) / (A * S + C * y)
```

两者最关键的区别不在分子，而在分母：

- 当前代码使用 `|y|`，只保留了纵向趋势的大小
- 参考文章使用 `y`，同时保留了纵向趋势的方向

这会带来本质不同的行为。

### 当前代码中的 `|y|`

`|y|` 只表达一件事：

- “弯变大了”

所以只要弯道趋势增强，不论左右方向，分母都会变大，整体误差被压小一些。  
这种处理本质上是统一降增益，目的是：

- 防止急弯时输出过猛
- 提高左右方向的一致性
- 避免分母过小或变号
- 简化现场调参

### 参考文章中的 `y`

带符号的 `y` 表达的是两件事：

- “弯变大了”
- “而且这个弯是往哪一边变化”

这意味着在某些关键姿态下，分母可能减小，控制输出会被放大；在另一些姿态下，分母可能增大，控制输出会被压住。  
于是分母不再只是做统一归一化，而是在改变误差曲线的局部斜率。

这也是参考文章强调“内环反馈方向修正”的原因：  
它的目标不是简单让误差更大，而是让关键区域里的反馈方向和灵敏度更合理。

## 为什么说当前版本“没有把方向修正吃满”

当前公式已经把 `LM - RM` 放进了分子，所以车已经能“提前感知弯道”。  
但由于分母里使用的是 `|LM - RM|`，方向信息在这里被抹掉了。

结果是：

- 当前算法已经有弯道提前量
- 但分母只能做“统一收增益”
- 不能按方向去改误差曲线的形状

换句话说：

- 分子负责“知道弯来了”
- 文章中的分母还能负责“知道该往哪边更积极地修”
- 当前分母则只会说“弯大了，先整体稳一点”

所以当前版本更稳健，但不如参考文章那样激进地修正内环关键区域的反馈特性。

## 对高速与急弯的实际影响

### 直道

直道上 `LM - RM` 通常接近 0，此时控制主要靠 `L - R`。  
当前公式和参考文章公式在这里差别很小。

### 急弯入口

急弯入口最典型的特征是：

- `LM - RM` 先明显变化
- `L - R` 还没有完全拉开

这意味着纵电感先看到“前面已经不是直线”。  
在这种时刻：

- 当前公式会先给一点提前转向，同时略微降低整体增益
- 参考文章公式则可能进一步改变该区域的反馈灵敏度，使车更早、更果断地进入转向

### 持续大曲率场景

例如圆桶内壁、长时间贴着圆弧跑的场景：

- `LM - RM` 会持续较大
- `L - R` 不一定一直大到足够明显

当前公式由于分母随着 `|LM - RM|` 增大而持续抬高，容易表现成：

- 控制器知道这是大弯
- 但整体保持偏保守
- 真正强力纠偏更依赖后续 `L - R` 继续拉开

这会让控制更平稳，但在附着不够时，也更容易在后段用过大的轮速差去“补救”。

## 为什么这会放大桶壁单轮空转风险

圆桶内壁或类似大曲率、高附着需求场景中，常见链条是：

1. `LM - RM` 已经很大，说明曲率很强
2. `L - R` 还不足以让控制器立即给出很大的纠偏
3. 车体转向介入偏晚
4. 后面为了追回轨迹，差速被一下打大
5. 轮胎附着不够时，就会出现一边轮子高速空转、车体实际位移不足

因此，桶壁打滑不只是电机或轮胎问题，也和传感器层对“急弯早期”的表达方式有关。

## 当前写法的优点与代价

### 优点

- 更稳，不容易炸
- 左右弯的增益变化更对称
- 分母不容易变得过小
- 更适合 8051 现场调参
- 对电感不完全对称的容忍度更高

### 代价

- 对关键弯道姿态的方向性增强不够
- 内环或持续大曲率区域的提前纠偏力度偏保守
- 更依赖后续 `L - R` 真正拉开后再补偿
- 在极限速度下，更容易把问题传递到后级差速和轮胎附着上

## 当前阶段的结论

当前实现不是错误实现，而是一种更偏保守、稳健的落地版本：

- `B * (LM - RM)` 负责引入弯道趋势
- `C * |LM - RM|` 负责在弯道里统一收增益

它的长处是先跑稳、好调、不容易失控。  
它的短处是没有完全利用带符号分母去修正内环关键区域的反馈特性。

因此，后续如果继续优化高速急弯和桶壁表现，可以沿两个方向推进：

1. 不改公式骨架，继续在速度调度、打滑检测和状态机上做增强
2. 在确认左右电感一致性与分母保护后，再评估是否尝试更接近“带符号分母”的写法
