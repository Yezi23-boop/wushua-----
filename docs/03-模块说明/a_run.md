# a_run 模块

## 模块职责

`a_run.c` 是定时任务主链，负责把电感采样、姿态刷新、元素仲裁、控制器更新和电机输出串成固定周期流程。

## 对外入口函数

- `run_time_1()`
- `run_time_2()`
- `run_time_3()`
- `a_run_apply_iap_guard()`

## 依赖与被依赖关系

依赖：

- `ADC`
- `imu`
- `pid`
- `motor`
- `a_run_mode`
- `a_run_track_element`
- `a_run_fly`
- `soft_timer`

被依赖：

- `isr.c` 的 `TM0_IRQHandler()` 和 `TM1_IRQHandler()`

## 关键运行数据

- `flat_fly`：飞坡/跷跷板阶段标志，由 `a_run_fly` 推进
- `left_target` / `right_target`：左右轮目标速度，供调试显示
- `speed_active`：本周期实际参与速度环计算的基础速度

## 高频路径注意事项

- `run_time_1()` 运行在 5ms 中断中，是最关键的实时控制路径
- `run_time_2()` 运行在 10ms 中断中，负责监测、启停状态和软件定时器
- `run_time_3()` 当前未挂接到中断主链，若重新启用必须先确认不会与现有控制链冲突
- 飞坡 RECOVER 阶段当前只限制前段转向并做阶梯提速，不再强制清零电机输出

## 运行逻辑概览

`run_time_1()` 的核心顺序是：

1. IAP 保护处理
2. 电感采样
3. 编码器读取
4. 读取启停状态
5. 刷新 `gyro_z`
6. 更新赛道元素仲裁和圆环积分
7. 分频更新转向外环
8. 飞坡/跷跷板速度策略
9. 圆环目标角速度覆盖
10. 角速度内环
11. 左右速度环
12. 运行态才输出电机，否则输出 0

`run_time_2()` 的核心顺序是：

1. 扫描最大值
2. 更新起跑状态
3. 丢线检测
4. 电压检测
5. 堵转检测
6. 预启动阶段设置负压百分比
7. 更新软件定时器

`TM1_IRQHandler()` 在 `run_time_2()` 后还会执行 `tim1_irq_handler`。当前该回调指向 `timer1_service_10ms()`，负责按键扫描和菜单 10ms 节拍。

## 调参与常见风险

- 如果车辆表现为“能跑，但偶发慢半拍”，优先怀疑高频链里数据更新顺序
- 如果改了参数却感觉没有立即生效，要确认修改路径是否经过 `control_apply_config()`
- 如果比赛态需要极限性能，尽量不要往 `run_time_1()` 再加调试输出
- 如果跷跷板落地后打滑，优先看 `a_run_fly` 的 RECOVER 限转向时间、阶梯速度和丢线屏蔽窗口
