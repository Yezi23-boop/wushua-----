# Air Dual Speed Loop Autotune Debug Memory

## 2026-03-24 confirmed PWM range memory

Goal:
- lock in the real command ranges so future conversations do not fall back to the old `4000` wheel assumption

Verified facts:
- wheel motor PWM is real `0~10000`
- `AT_FUYA` vacuum command remains `0~4000`
- fresh hardware verification on `COM8` confirmed wheel open-loop commands at `5000`, `7000`, and `9000`
- a full `pwm-map` run then completed to `10000`

Default rule update:
- treat wheel PWM as `0~10000` in `air-dual`, `ground-dual`, `pwm-identify`, and `pwm-map`
- treat `AT_FUYA` as `0~4000`
- do not reintroduce the old `4000` wheel limit unless a future board image proves otherwise

这份文档用于沉淀架空双轮 `air-dual` 调试里已经验证过的经验，避免后续会话重复踩坑。
带负载双轮请改写 `ground_dual_debug_memory.md`。

使用规则：
- 每次实测后先写“已验证事实”，再写“推断”
- 只有重复验证过的结论，才能进入“下一轮默认策略”
- 如果新结论推翻旧结论，不删除旧记录，直接标记“已替代”

## 当前已验证事实

### 2026-03-20 架空 `autotune` 首轮稳定实测

目标：
- 继续使用当前 `autotune` 链路做架空速度环调试
- 左右轮允许不同 PID
- 负压关闭

已验证事实：
- `COM8` 串口链路稳定，可以持续读到大量样本。
- `TEST_speed` 多段切换在架空 `autotune` 链路里是可行的。
- 相邻重复目标值不适合按旧方法硬拆，`45 -> 45` 更适合按 `45:1000` 合并分析。
- 架空 `autotune` 里，`stop_flag` 不是最可靠的结束判据；尾部显式发送 `TEST_speed=0` 更稳。
- 单轮调试时，把另一侧 PID 直接设为 `0/0/0` 是有效隔离手段。
- 当前左轮明显比右轮更难调，应优先处理左轮。
- 左轮隔离时，`L = 100 / 20 / 0` 比 `L = 95 / 20 / 0` 更稳。

推断：
- 左轮当前的主要矛盾更像低速起步段波动，而不是全速度段都需要继续下压 `Kp`。

默认策略更新：
- 默认先看左轮
- 默认允许左右轮不同 PID
- 默认使用单轮隔离

### 2026-03-21 调参规则补充

目标：
- 固化当前已经验证有效的调参规则
- 避免后续新对话重复踩坑

测试条件：
- 端口：`COM8`
- 模式：架空 `autotune`
- 速度序列：原始目标常为 `15:500,25:500,35:500,45:500,45:500,35:500,25:500`，分析时按 `45:1000` 合并
- 左右轮 PID：允许不同
- 单轮隔离：是
- 负压：`0`

已验证事实：
- `miss` 在当前架空调试里经常更像采样窗口边界问题，不能直接当作 PID 差。
- 编码器速度绝对值大于 `200` 的样本不可信；已实测轮子占空比最大时，编码器值不会超过 `200`。
- 单轮隔离搜索和双轮 A/B 联合使用，能比只看单轮最低分更可靠。

推断：
- 后续分析时，应默认先过滤“编码器速度绝对值大于 200”的异常样本。
- 后续人工判断时，应默认把 `miss` 当作“待排查样本”，而不是直接作为淘汰依据。

默认策略更新：
- 新增独立规则文档 `docs/tuning_rules.md`
- `miss` 默认先忽略，不直接用于否定某组 PID
- 编码器速度绝对值大于 `200` 时，默认视为异常样本并过滤
- 当前整车默认保留基线：
  - 左轮：`100 / 20 / 0`
  - 右轮：`105 / 20 / 0`

下一步：
- 如果继续调左轮，优先盯住低速起步段，而不是继续大幅改 `Kp`
- 如果继续调右轮，先以 `105 / 20 / 0` 为基线，只做窄范围邻域比较

### 2026-03-21 两组序列联合复验补充

目标：
- 用第一组 `500ms` 和第二组 `300ms` 同时复验左轮新候选
- 判断 `L = 99 / 20 / 0` 是否能替代当前左轮基线

测试条件：
- 串口：`COM8`
- 模式：架空 `autotune`
- 负压：`0`
- 第一组：`15:500,25:500,35:500,45:500,35:500,25:500,25:500`
- 第二组：`15:300,25:300,35:300,45:300,35:300,25:300,25:300`
- `miss` 默认忽略
- 编码器速度绝对值大于 `200` 的样本直接过滤

已验证事实：
- `L = 99 / 20 / 0` 在部分左轮单轮隔离轮次和部分双轮轮次里，确实会跑出比 `L = 100 / 20 / 0` 更低的分数。
- 但把 `L = 99 / 20 / 0` 放回双轮，并补做第二组 `300ms` 快节奏复验后，波动明显增大，没有稳定压过基线。
- `L = 99.5 / 20 / 0` 与 `L = 99.8 / 20 / 0` 这两个中间点，也没有稳定解决这个问题。
- 右轮 `R = 105 / 21 / 0` 曾短暂优于 `R = 105 / 20 / 0`，但重复验证后没有形成稳定收益。

推断：
- 左轮当前主要矛盾仍然是快节奏序列下的偶发波动，单次低分还不能直接升级成默认值。
- 当前更适合把 `L = 99 / 20 / 0` 作为后续可复验候选，而不是直接替换基线。

默认策略更新：
- 当前整车默认继续保留：
  - 左轮：`100 / 20 / 0`
  - 右轮：`105 / 20 / 0`
- `L = 99 / 20 / 0` 降级为“已观察到潜力，但尚未稳定复现”的候选值。

### 2026-03-21 左轮 `Ki=19.5` 小步试探与回退

目标：
- 围绕当前左轮基线 `100 / 20 / 0` 做更小步长的人工微调
- 判断 `L = 100 / 19.5 / 0` 是否能在不放大快节奏波动的前提下改善左轮低速段

测试条件：
- 串口：`COM8`
- 模式：架空 `autotune`
- 负压：`0`
- 第一组：`15:500,25:500,35:500,45:500,35:500,25:500,25:500`
- 第二组：`15:300,25:300,35:300,45:300,35:300,25:300,25:300`
- 补充低速组：`15:500,25:500,15:300,25:300,35:300,25:300`
- `miss` 默认忽略
- 编码器速度绝对值大于 `200` 的样本直接过滤

已验证事实：
- 左轮单轮隔离里，`L = 100 / 19.5 / 0` 曾跑出比 `100 / 20 / 0` 更低的综合分，也有更低的低速平均误差。
- 但把 `L = 100 / 19.5 / 0` 放回双轮，并对第一组、第二组做交错复验后，结果没有稳定压过整车基线。
- 继续把右轮也一起改成 `R = 105 / 19.5 / 0` 后，整车重复性反而更差。
- 最后再做只改左轮的交错 A/B 复验时，`L = 100 / 19.5 / 0, R = 105 / 20 / 0` 仍然出现了右轮大幅波动，而 `100 / 20 / 0 + 105 / 20 / 0` 两轮都稳定落在低分区间。

推断：
- `L = 100 / 19.5 / 0` 目前更像“在部分轮次有效的候选值”，还不够稳定，不能升级成新的默认参数。
- 当前整车基线的重复性仍然更强，尤其是在交错复验里更可靠。

默认策略更新：
- 当前整车默认继续保留：
  - 左轮：`100 / 20 / 0`
  - 右轮：`105 / 20 / 0`
- `L = 100 / 19.5 / 0` 记录为“低速段有潜力，但整车复验未坐实”的候选值。

### 2026-03-24 `15` 速段高分根因排查

目标：
- 判断当前偶发的高分到底来自真实控制变差，还是来自低速段评分过于敏感
- 避免继续围绕假信号盲改 PID

测试条件：
- 串口：`COM8`
- 模式：架空 `autotune`
- 当前整车基线：
  - 左轮：`100 / 20 / 0`
  - 右轮：`105 / 20 / 0`
- 第一组：`15:500,25:500,35:500,45:500,35:500,25:500,25:500`
- 第二组：`15:300,25:300,35:300,45:300,35:300,25:300,25:300`
- `miss` 默认忽略
- 编码器速度绝对值大于 `200` 的样本直接过滤

已验证事实：
- 在基线下连续重复跑第一组和第二组时，`25/35/45` 这些速度段的均速和分数都非常稳定。
- 偶发的高分几乎都集中在 `15` 速段，而不是整条多段序列一起变坏。
- 即使 `15` 速段被打出高分，实际均速仍然大多稳定在 `14.0` 到 `14.5` 左右，并没有出现明显失控。
- 把 `15` 速段的细项指标拆开后，高分主要来自 `settle_ratio` 偶发跳高；`rise_ratio`、`steady_error` 和均速并没有同步恶化到同等程度。

推断：
- 当前架空调试里，`15` 速段的评分对 `settle` 判定过于敏感，容易把轻微边界波动放大成高分。
- 继续围绕这类单段高分去盲改 PID，收益很低，反而更容易把原本稳定的参数带偏。

默认策略更新：
- 当前继续保留整车默认基线：
  - 左轮：`100 / 20 / 0`
  - 右轮：`105 / 20 / 0`
- 后续人工判断时，若只有 `15` 速段高分、但均速仍接近目标，则默认先视为“评分敏感段”，不直接据此改 PID。
- 后续优先观察 `25/35/45` 这些更稳定、区分度更高的速度段。
